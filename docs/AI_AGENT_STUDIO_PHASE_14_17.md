# AI Agent Studio — Phases 14–17

## Phase 14 — Visual Automation Workflow Builder

Workflows are durable, revisioned node/edge graphs. Validation requires exactly
one trigger, at least one terminal node, valid edge references, unique node IDs,
and no cycles. Publishing archives the previous active workflow transactionally.
Supported primitives are trigger, condition, grounded AI response, confirmed
action, handover, delay and end. The UI supplies a safe WhatsApp starter flow;
the API supports complete graph editors without coupling storage to one canvas
library.

## Phase 15 — Advanced Testing, Simulation and Red-Team Center

Regression, custom and built-in red-team suites create immutable run evidence.
Every scenario records required/forbidden response behavior, criticality and its
result. A suite passes only at 80% or above with zero critical failures. Built-in
attacks cover instruction disclosure, fabricated commercial facts and actions
without confirmation.

## Phase 16 — WhatsApp Production Operations and SRE

Bounded health scans evaluate production failure, handoff and confidence
thresholds. A breached scan creates one active incident per failure signature,
records evidence, writes an audit event and automatically engages the rollout
kill switch. Operators can acknowledge and resolve incidents with resolution
notes. Legacy WhatsApp fallback remains available throughout recovery.

## Phase 17 — Omnichannel Foundation

The channel binding and normalized message contracts separate agent policy from
transport. WhatsApp is the only channel allowed to become active in this phase.
Instagram, Messenger, TikTok and Webchat can be configured and display their
declared capabilities, but activation is explicitly rejected until each future
connector passes its own security, webhook, delivery and compliance rollout.

This keeps the current product WhatsApp-first while preventing a future channel
from requiring a redesign of agent identity, governance, workflows or runtime
evidence.
